# 📜 造纸智能助手「小纸」— 源码阅读指南

> 建议阅读耗时：1-2 小时 | 总有效代码：约 2000 行

---

## 项目概述

这是一个 **造纸工艺垂直领域智能问答系统**，支持两种工作模式：

| 模式 | 说明 |
|------|------|
| 🔍 知识问答 | 意图识别 → 三阶段检索 → RAG Prompt → LLM 生成 |
| 🤖 故障排查 Agent | ReAct 循环（Thought → Action → Observation），3 个 Tool Calling 工具 |

核心技术栈：

| 层 | 技术 |
|---|---|
| LLM | DeepSeek-V3（OpenAI 兼容 API） |
| Embedding | BAAI/bge-small-zh-v1.5（本地 CPU 推理） |
| 向量库 | ChromaDB（嵌入式持久化） |
| 关键词检索 | 自实现 BM25 + jieba 中文分词 |
| 精排 | BGE CrossEncoder Reranker（bge-reranker-v2-m3） |
| 前端 | Streamlit |
| 框架 | LlamaIndex + 原生 OpenAI SDK |

**检索链路**：

```
用户问题 → HybridRetriever (BM25+语义融合, α=0.3)

         → Top-5 文档 → LLM 生成回答
```

## 推荐阅读顺序（自底向上，10 步走）

### 第 1 步：项目入口 — 了解怎么跑起来的

| 文件 | 行数 | 要点 |
|------|------|------|
| `run.py` | ~100 | CLI 知识问答入口，调用链：`build_retriever()` → `PaperAgent` → `agent.chat()` |
| `run_agent.py` | ~120 | CLI Agent 模式入口，调用链：`build_retriever()` → `PaperReActAgent` → `agent.chat()` |
| `app.py` | ~440 | Streamlit Web 界面，双模式切换 + 思考链可视化 + 反馈按钮 |

这三个文件看完就能理解整个系统的调用链路。`app.py` 最长但结构清晰：CSS 样式 → Session 初始化 → 侧边栏 → 消息渲染 → 双模式处理分支。

---

### 第 2 步：数据摄入层 `src/ingestion/` — 数据怎么进来

| 文件 | 行数 | 核心逻辑 |
|------|------|----------|
| `parser.py` | ~50 | PDF 解析：PyMuPDF（快速主引擎）+ pdfplumber（兜底），双引擎策略 |
| `splitter.py` | ~75 | 中文文档智能分块：先按章节标题正则切分（`第X章`、`一、二、` 等模式），再按段落合并，chunk_size=500, overlap=80，保证不截断术语 |

两者都非常简短，看完就懂数据是怎么从 PDF 变成文本片段的。

---

### 第 3 步：索引构建层 `src/indexing/` — 索引怎么建

| 文件 | 行数 | 核心逻辑 |
|------|------|----------|
| `vector_store.py` | ~70 | ChromaDB 封装：持久化存储、BGE Embedding、按 source 字段去重写入 |
| `bm25_index.py` | ~148 | ⭐ **自实现 BM25**（非调库）：jieba 分词、IDF 预计算、TF 饱和函数（k1=1.5, b=0.75）、pickle 持久化。这是项目最有"技术含量"的模块之一 |
| `indexer.py` | ~100 | 一键建库入口：`parse PDF → split → write Chroma → build BM25 → return HybridRetriever` |

**重点看 `bm25_index.py`**，完全手写 BM25 算法而非调用 `rank_bm25` 库，包含了完整的 TF-IDF 计算、文档长度归一化、索引持久化逻辑。

---

### 第 4 步：检索层 `src/retrieval/` — 检索引擎核心 ⭐

| 文件 | 行数 | 核心逻辑 |
|------|------|----------|
| `hybrid_retriever.py` | ~110 | **混合检索**：BM25 + Chroma 语义向量各自检索 candidate_pool=20 条 → min-max 归一化 → 加权融合（α=0.3，BM25 占 30%，语义占 70%）→ 返回 Top-N。对外暴露与 Chroma 一致的 `.query()` 接口 |
| `reranker.py` | ~110 | **CrossEncoder 精排**：先用 Hybrid 召回 20 条候选 → BGE Reranker 逐对打分 → 权威来源加权（含"访谈录""标准""专利""院士"等关键词的文档 ×1.3）→ 排序返回 Top-N |
| `factory.py` | ~78 | **检索器工厂**：`build_retriever()` 统一入口，自动 seed 数据 + 组装三阶段检索链。被 CLI、Streamlit、Eval 三处复用 |

这是整个项目的核心引擎。三个文件采用 **装饰器模式** 层层包裹：`RerankerProcessor(HybridRetriever(Chroma, BM25Index))`，每一层都有相同的 `.query()` 接口，可以任意组合替换。

---

### 第 5 步：生成层 `src/generation/` — RAG 问答模式

| 文件 | 行数 | 核心逻辑 |
|------|------|----------|
| `prompts.py` | ~44 | 4 套 Prompt 模板：`SYSTEM_PROMPT`（身份定义）、`CHAT_RULES`（闲聊规则）、`RAG_RULES`（知识问答规则）、`RAG_QA_PROMPT`（检索增强模板，含 `{context}` 和 `{question}` 占位符） |
| `rag_pipeline.py` | ~168 | ⭐ **PaperAgent 类**：意图分拣（关键词匹配 `_is_chat()` → chat/rag 分流）+ 对话记忆（最近 10 轮）+ RAG 检索生成 + 知识库空结果兜底 |

`PaperAgent` 的设计要点：
- `_is_chat()` 用简单关键词集合做意图识别（"你好""你是谁""谢谢"等），≤3 字的短输入也归为闲聊
- 闲聊走 `deepseek-v4-flash` 直接回复（temperature=0.7, max_tokens=512）
- 知识问答走 `检索 → RAG Prompt → 生成`（temperature=0.3, max_tokens=1024）
- 检索结果为空时，走 fallback 拒答

---

### 第 6 步：Agent 层 `src/agent/` — 故障排查模式 ⭐

| 文件 | 行数 | 核心逻辑 |
|------|------|----------|
| `tools.py` | ~177 | 3 个 OpenAI function-calling 工具定义 + `ToolExecutor` 执行器：`search_knowledge`（通用检索）、`query_tool_list`（设备清单查询，自动追加"设备 工具 仪器 装置 参数"关键词）、`check_common_mistakes`（故障查询，自动追加"常见故障 注意事项 错误 问题 缺陷"关键词）。每个工具都在底层做了 query augmentation |
| `react_agent.py` | ~332 | ⭐ **PaperReActAgent 类**：完整 ReAct 循环，max 10 轮迭代，Tool Calling → 结果回填 messages → 继续推理。支持 `on_thought` callback（供 Streamlit 可视化思考链）。超限强制收束 + API 异常重试 |

**Agent 工作流**：

```
用户问题
  │
  ▼
LLM 决策 (带 3 个 Tool Definition)
  ├─ 需要检索 → 调用 search_knowledge / query_tool_list / check_common_mistakes
  │              → ToolExecutor 执行 → 结果回填 tool role message
  │              → LLM 再次决策
  └─ 信息充足 → 直接输出最终回答
  │
  ▼
三段式输出：🛠 准备工作 → 📋 分步教学 → ⚠️ 避坑指南
```

关键设计细节：
- 使用 OpenAI 原生 Tool Calling 协议（非 LlamaIndex ReActAgent），更灵活
- 每轮迭代都带上完整 messages 历史（含 tool 调用结果），LLM 可以跨轮引用
- max_iterations=10 是安全阀，超限后强制要求 LLM 给出最终回答
- 首轮 API 调用失败会重试一次（将错误信息注入 messages 让 LLM 自行调整）

## 项目亮点总结

1. **自实现 BM25**：不调库，完整手写 TF-IDF + BM25 算法，包含索引持久化
2. **三阶段检索**：BM25 关键词 + BGE 语义向量 + CrossEncoder 精排，层层递进
3. **装饰器模式**：检索链每层都有相同的 `.query()` 接口，任意组合替换
4. **原生 Tool Calling**：不走 LlamaIndex 封装的 ReActAgent，直接用 OpenAI 协议，更灵活可控
5. **思考链可视化**：通过 `on_thought` callback 将 Agent 推理过程实时展示给用户
6. **完善的评测体系**：RAG 检索 + Agent 回答质量双轨评测，支持难度分层
