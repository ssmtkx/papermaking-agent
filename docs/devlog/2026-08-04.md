## 三、第一轮修复（3 高危 + M4 + 清理）

### 3.1 H1 — 修复意图识别误判

`src/generation/rag_pipeline.py`

**根因**：
- `len(q) <= 3` 把「打浆」「施胶」「气泡」「AKD」这类 2-3 字的技术术语全部路由到闲聊分支
- `_CHAT_KEYWORDS` 里的 `介绍一下`、`你是` 做子串匹配，「介绍一下AKD施胶的用量」会被误判

**修复**：删除短输入启发式；`_CHAT_KEYWORDS` 中 `介绍一下` → `介绍一下你自己`、移除过宽的 `你是`。

**实测**：`打浆`/`介绍一下打浆流程` → 走检索；`你好`/`你是谁`/`介绍一下你自己` → 走闲聊 ✅

### 3.2 H2 — 修复 out-of-KB recall 虚高

`src/eval/evaluator.py`

**根因**：`recall = sum(rel)/len(rel_texts) if rel_texts else 1.0`，`relevant_chunk_indices` 为空时 recall 恒为 1.0。`eval_qa.json` 有 8 条知识库外数据，系统性抬高平均 recall。

**修复**：rel_texts 为空时 recall 计 `0.0`。

**实测**：out-of-KB 条目 recall@5 从 1.0 → 0.0 ✅

### 3.3 H3 — BM25 缓存失效校验

`src/indexing/bm25_index.py` + `src/indexing/indexer.py`

**根因**：`build_hybrid_from_collection` 只要 `data/bm25_index.pkl` 存在就直接加载，不校验是否与当前集合一致。`import_qa` 重新导入（先删后加）后，Chroma 是新材料、pkl 还是旧文本，检索会返回已不在集合中的文档。

**修复**：
- `BM25Index` 新增文档指纹 `_doc_signature`（sha1 over 文档列表），build/save/load 联动持久化
- 加载缓存前用 `collection.get()` 的指纹比对，不匹配自动重建并提示 `[!] BM25 cache is stale — rebuilding...`

**实测**：缓存匹配→加载；缓存过期→重建；签名 roundtrip 一致 ✅

### 3.4 M4 — ReAct 强制收尾补触发回调

`src/agent/react_agent.py`

强制收尾路径（max_iterations 触发）补上 `self._emit("answer", answer)`，与正常路径对齐，Streamlit 思考链不再缺最后一步。

### 3.5 清理

`src/eval/evaluator.py`：`_ndcg(rel, scores)` 移除未使用的 `scores` 死参数；`print_report` 修正「知识库文档」错误标签为「覆盖类别」。

## 四、第二轮修复（中危 + 性能 + 清理）

### 4.1 M1 — build_index 全量 BM25 + rebuild_index 简化

- `src/indexing/indexer.py`：`build_index` 的 BM25 改为从全量 `collection.get()` 构建并落盘缓存（覆盖 seed / 已导入 QA + 本次 PDF）
- `src/retrieval/factory.py`：`rebuild_index` 简化为「清缓存 + 委托 build_index」，顺带清理不再使用的 `BM25Index` / `HybridRetriever` / `Optional` import

### 4.2 _search_one 性能优化

`src/retrieval/hybrid_retriever.py`：BM25 融合从 `for i in range(len(_doc_texts))` 全量扫描改为直接遍历 `bm25_map.items()`，O(N) → O(命中数)。

**实测**：融合结果与修复前完全一致（文档排序、分数不变）✅

### 4.3 超长段落切分

`src/ingestion/splitter.py`：新增 `_split_long_paragraph`（按句末边界 `。！？；` 切分）和 `_hard_split`（单句仍超长时兜底硬切），chunk 上限约束在 `chunk_size + overlap` 内。

**实测**：181 字单句段落从「整段 181 字」变为 8 段 ≤61 字；多句段落按句末边界切分、不在句中截断 ✅

> 注：splitter 改动只影响**未来重建索引**时的 PDF 解析，不影响已建好的 Chroma 集合。

### 4.4 M2 — 评测基准一致性检查

`eval_rag.py`：`build_retriever` 增加基准一致性检查，当集合缺少 seed 基准块时输出明确警告（提示先运行 `seed_data.py`），避免评测全 MISS 却无感知。

### 4.5 清理

- `app.py`：`sys.path.insert` 移到 src 导入之前
- `src/generation/rag_pipeline.py`：`PaperAgent` 增加 `model` 参数（支持 `DEEPSEEK_MODEL` 环境变量），替换三处硬编码模型名

## 七、前端国风重构（宣纸·水墨主题）

### 7.1 背景

前端此前为 Streamlit 默认绿色风格，视觉上与「造纸」这一中国传统题材脱节，也缺乏生活气息。本次将前端整体重构为 **宣纸·水墨（书斋文人）** 国风主题：宣纸米黄底 + 墨色 + 朱砂印红 + 鎏金点缀，配合信笺红格、印章、回纹、工序卡片等元素，并用暖调配色与俏皮文案注入生活气息。

**原则：只改前端观感与结构，后端检索 / Agent / 评测 / 消息数据结构零改动。**

### 7.2 设计系统

| 语义 | 色值 | 用途 |
|------|------|------|
| 宣纸米黄 | `#F6F0E4` | 应用底色 |
| 朱砂印红 | `#A63A2B` | 主色（按钮 / 印章） |
| 浓墨 | `#2F2A25` | 标题 |
| 黛蓝 / 竹青 / 鎏金 | `#3B5568 / #5B7F5E / #C9A227` | 工序「思/观」、点缀 |
| 墨褐 | `#352A21` | 侧栏面板 |

- **字体**：标题宋体、品牌楷体（离线系统栈，国内不引 Google Fonts）
- **纸纹**：CSS 多层渐变 + 内联 SVG `feTurbulence` data-URI（纯本地）
- **元素**：双线红框印章、信笺横格气泡、朱砂「引」注、鎏金回纹分隔线

### 7.4 生活气息细节

- 侧栏按星期自动切换一句今日提示（如「今日 · 研究一下制浆和抄纸的工艺参数吧」）
- 侧栏底部一行小标语：「制浆 · 抄纸 · 施胶 · 涂布，有问必答」
- 思考链 → **思考过程**：`①思考(黛蓝) ②行动(朱砂) ③观察(竹青) ④完成(鎏金)`
- 来源 → **引用来源**：宣纸卡片 + 朱砂「引」章

- 气泡：助手 = 信笺红格纸卡，用户 = 黛墨深底白字；头像为本地 SVG 印章（助手朱砂「纸」/ 用户黛蓝「问」）
- 文案整体采用**自然口语**风格（欢迎语、spinner、输入框占位符等），不做文言化；国风味主要由视觉（纸纹 / 印章 / 配色 / 字体）承担
- **图标**：界面 emoji 替换为更克制的方案——横幅模式图标用内联 SVG（Feather 描边，`currentColor` 随文字变色），favicon 与气泡头像用本地 SVG 印章（`assets/*.svg`），Streamlit 原生元素（radio / 按钮 / 折叠标题 / 反馈）改纯文字；CLI 与评测脚本的 emoji 保留不动
- **模式介绍卡**：主页面横幅下方新增 `render_mode_intro`，随侧栏模式切换实时更新——展示当前模式（知识问答 / Agent 故障排查）的用途说明与两个示例问题（chip 样式），两模式用不同强调色（朱砂 / 黛蓝）区分
- **主界面布局**：主页面自上而下为 品牌横幅 →「小纸」介绍卡（`render_welcome`，原第一条欢迎消息改为静态卡片，对话起始为空）→ 当前模式介绍卡 → 聊天区
