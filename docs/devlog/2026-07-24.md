## 二、Phase 3 Agent 核心开发

### 2.1 工具封装 (`src/agent/tools.py`)

| 工具 | 功能 | 检索策略 |
|------|------|----------|
| `search_knowledge` | 通用造纸知识检索 | 原样查询 |
| `query_tool_list` | 某工艺环节的设备/工具/仪器查询 | 关键词增强："{technique} 设备 工具 仪器 装置 参数" |
| `check_common_mistakes` | 某工序的常见错误/故障/注意事项 | 关键词增强："{step} 常见故障 注意事项 错误 问题 缺陷" |

- 工具定义遵循 OpenAI function-calling schema
- `ToolExecutor` 类统一管理工具调度，返回格式化结果（标题 + 来源标注）
- 异常安全：每个工具调用有 try/catch，返回 `[ERROR]` 而非抛异常

### 2.2 ReAct Agent (`src/agent/react_agent.py`)

**`PaperReActAgent` 类** — 核心特性：

| 特性 | 实现 |
|------|------|
| ReAct 循环 | 标准 Thought→Action→Observation 循环，最大 10 轮 |
| Tool Calling | OpenAI function-calling 协议，对接 DeepSeek-V3 |
| 造纸专家人设 | 30 年经验老师傅，三段式回答格式 |
| 结构化输出 | 🛠 准备工作 → 📋 分步教学 → ⚠️ 避坑指南 |
| 对话记忆 | 最近 10 轮 user/assistant 对（不含 tool 消息） |
| 异常处理 | API 调用失败自动重试一次；超轮次强制输出 |
| `on_thought` 回调 | 可注入回调函数，供 Streamlit 可视化思考链 |

**System Prompt 要点：**
- 工具选择指南（何时用哪个工具）
- 三段式回答格式模板
- 6 条核心规则（只靠工具结果、必须标来源、诚实拒答、范围限定等）

### 2.3 CLI 入口 (`run_agent.py`)

```bash
python run_agent.py   # 启动 Agent 模式交互对话
```

- `/help` `/clear` `/quit` `/index` 四个斜杠命令
- 实时显示 ReAct 思考过程（🔧 工具调用 / 📖 观察结果）
- 每轮结束后显示迭代次数和工具调用统计

### 2.4 与简单 RAG 模式的区别

| 维度 | `run.py` (简单RAG) | `run_agent.py` (Agent) |
|------|-------------------|----------------------|
| 检索方式 | 一次检索，直接生成 | 多轮检索，LLM 自主决定何时检索/用何工具 |
| 工具选择 | 无（固定检索链路） | LLM 根据问题类型选择 3 个工具 |
| 输出格式 | 自由文本 | 三段式结构化输出 |
| 复杂问题 | 一次检索覆盖不足 | 可多次检索不同角度，综合回答 |
| 思考可见性 | 不透明 | 每步 Thought/Action/Observation 可见 |

## 六、Phase 5 Docker 容器化

### 6.1 文件清单

| 文件 | 说明 |
|------|------|
| `Dockerfile` | 基于 `python:3.10-slim-bookworm`，CPU-only PyTorch |
| `docker-compose.yml` | 单服务编排，含 model_cache + chroma_data + data 三个 volume |
| `.dockerignore` | 排除 `__pycache__`、`.env`、`chroma_db/`、评测脚本等 |
| `streamlit.config.toml` | Streamlit 绿色主题 + headless 配置 |

### 6.2 镜像设计

```
FROM python:3.10-slim-bookworm
├── build-essential (chromadb SQLite)
├── pip install requirements.txt + torch (CPU)
├── COPY src/ scripts/ app.py run.py run_agent.py
├── ENV HF_ENDPOINT=https://hf-mirror.com
└── ENTRYPOINT: streamlit run app.py
```

**分层策略：**
- requirements.txt 先 COPY 再 pip install → 依赖层缓存
- 源码最后 COPY → 改代码只需重建最上层

**模型处理：**
- BGE 模型不在 build 时下载（避免网络不稳定导致构建失败）
- 运行时首次自动下载到 `/app/.cache/huggingface`
- docker-compose 的 `model_cache` volume 持久化，重启不丢失

### 6.3 使用方式

```bash
# 1. 确保 .env 已配置 DEEPSEEK_API_KEY
cp .env.example .env   # 编辑填入 API Key

# 2. 构建
docker compose build

# 3. 启动（后台）
docker compose up -d

# 4. 访问
open http://localhost:8501

# 5. 放入 PDF 后重建索引
# 在 Streamlit 侧边栏或 CLI 中执行 /index

# 6. 停止
docker compose down
```

### 6.4 Volume 设计

| Volume | 容器路径 | 用途 |
|--------|----------|------|
| `model_cache` | `/app/.cache/huggingface` | BGE 模型缓存 (~2.3GB) |
| `chroma_data` | `/app/chroma_db` | Chroma 向量库持久化 |
| `./data` (bind) | `/app/data` | PDF 文件 + 评测数据 |
