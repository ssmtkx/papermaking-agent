## 四、核心模块详解

### 4.1 文档摄入（ingestion）

| 文件 | 功能 | 关键技术点 |
|------|------|-----------|
| `parser.py` | PDF → 纯文本 | PyMuPDF 主引擎，pdfplumber 兜底；`parse_directory()` 批量处理 |
| `splitter.py` | 文本 → 语义块 | 正则匹配章节标题（一、/1./第X章）；段落级合并，chunk_size=500, overlap=80 |

### 4.2 向量索引（indexing）

| 文件 | 功能 | 关键技术点 |
|------|------|-----------|
| `vector_store.py` | Chroma 向量库 | BAAI/bge-small-zh-v1.5 本地推理；按 source 去重更新 |
| `bm25_index.py` | BM25 关键词索引 | 自实现 BM25（k1=1.5, b=0.75）；jieba 中文分词；预计算 IDF |
| `indexer.py` | 统一建库入口 | `build_index()` 从 PDF 建；`build_hybrid_from_collection()` 从已有 Chroma 建 |

### 4.3 检索增强（retrieval）

| 文件 | 功能 | 关键技术点 |
|------|------|-----------|
| `hybrid_retriever.py` | 混合检索 | α=0.3 融合 BM25 + 语义分数；Min-Max 归一化；文档级去重 |
| `reranker.py` | 二阶段精排 | BAAI/bge-reranker-v2-m3 CrossEncoder；权威来源关键词检测（1.3× 加权） |

**检索链路：**
```
用户提问 → BM25(关键词) + Chroma(语义) → 融合 Top-20 → CrossEncoder 精排 → Top-3/5
```

### 4.4 对话生成（generation）

| 文件 | 功能 | 关键技术点 |
|------|------|-----------|
| `prompts.py` | Prompt 模板 | SYSTEM_PROMPT 定义人设"小纸"；CHAT_RULES / RAG_RULES 双模式规则 |
| `rag_pipeline.py` | PaperAgent | 意图分拣（关键词匹配：闲聊 vs 知识查询）；最近 10 轮对话记忆；双模式路由 |

**PaperAgent 架构：**
```
用户输入 → 意图检测
  ├─ 闲聊/问候 → 直接 LLM 回复（不查知识库）
  └─ 知识查询 → 检索 → RAG Prompt → DeepSeek-V3 生成
```

### 4.5 模拟知识库（scripts/seed_data.py）

- 制浆：打浆度控制、木浆分类、废纸脱墨

## 五、踩坑记录

| 问题 | 原因 | 解决 |
|------|------|------|
| HuggingFace 模型下载超时 | 国内网络屏蔽 huggingface.co | 设置 `HF_ENDPOINT=https://hf-mirror.com`，在 import 前注入环境变量 |
| Chroma 嵌入模型首次运行慢 | BGE 模型约 100MB 需下载 | 首次运行耐心等待，后续走本地缓存 |
| jieba 分词首次运行慢 | 需构建前缀词典缓存 | 首次有 1-2s 延迟，后续秒出 |
| `FlagEmbedding.FlagReranker.compute_score()` 报错 `prepare_for_model` | FlagEmbedding 与 transformers 版本不兼容 | 改用 `sentence_transformers.CrossEncoder`，API 更稳定 |
| Conda 环境路径问题 | Git Bash 不识别 `conda` 命令 | 使用完整 Python 路径 `D:\anaconda-environment\envs\paper_agent\python.exe` |
| Windows GBK 编码 | `print("✅")` 触发 UnicodeEncodeError | 使用 `python -X utf8` 或改用纯 ASCII 标记 `[OK]` |

| 知识库外 | 4 条 | 钛白粉、COD、车速、纳米纤维素 |

难度分层： easy 14 条 / medium 9 条 / hard 7 条

### 9.2 评测模块 (`src/eval/evaluator.py`)

`RAGEvaluator` 类，核心功能：
- 支持任意 `.query()` 接口的检索器（Chroma / Hybrid / Reranker）
- 指标：**Hit Rate@K、MRR@K、Recall@K、Precision@K、NDCG@K**
- 文档匹配：基于归一化文本前缀匹配（前 20 字符）
- 报告：难度分层、未命中列表、ASCII 可视化进度条

### 9.3 CLI 入口 (`eval_rag.py`)

```bash
python eval_rag.py                  # Hybrid 模式，K=1,3,5,10
python eval_rag.py --rerank         # + CrossEncoder 精排
python eval_rag.py --mode bm25      # BM25-only 对比
python eval_rag.py --mode semantic  # 语义-only 对比
python eval_rag.py --in-domain      # 只看知识库内（排除 OOD）
python eval_rag.py --save res.json  # 输出 JSON 报告
```

**BM25 适配**：`BM25Index.search()` 接口与 `retriever.query()` 不一致，通过 `_BM25Adapter` 统一为 `{"documents": [[...]], "distances": [[...]]}` 格式。

### 9.4 首批评测结果

| 模式 | Hit@5 | MRR@5 | Recall@5 | Precision@5 |
|------|-------|-------|----------|-------------|
| **Hybrid (α=0.3)** | **86.7%** | **86.7%** | **98.7%** | 25.3% |
| Hybrid + Reranker | 86.7% | 85.0% | 97.0% | 24.7% |
| Semantic only | 86.7% | 86.7% | 98.0% | 24.7% |
| BM25 only | 86.7% | 85.0% | 97.0% | 24.7% |

> **知识库内 26 条（`--in-domain`）：Hit@5 = 100%，MRR@5 = 100%，全部命中 ✅**

4 条未命中全是"知识库外"问题——系统正确返回空结果，符合预期。知识库内指标已大幅超越 Phase 2 的 89% 里程碑目标。

**模式对比结论：**
- 14 条小知识库上 Hybrid 略优于 Semantic（Recall@5 +0.7%），BM25 提供了边际增益
- Reranker 在小知识库上未展现优势，反而 @1 略有退化（q030 被降权），大库场景下价值才会凸显
- 4 种模式 Hit@5 持平，说明 BGE 语义向量在当前数据上已经非常准确
